# mTLS Certificate Support

VmManager Agent supports mutual TLS (mTLS) for secure communication with the BloomCE platform.

## Overview

The agent acts as an mTLS **server** (validating client certs) and as an mTLS **client** (fetching its own certs from a cert server). All cert paths are configurable via `settings.json` or `appsettings.json` under the `VmManager` config section.

## Certificate Paths

All paths have sensible defaults but can be overridden via config keys:

| Config Key | Default | File |
|------------|---------|------|
| `VmManager:ServerCertPath` | `C:\ProgramData\BloomCE\certs\agent_server_cert.pem` | Agent TLS server cert |
| `VmManager:ServerKeyPath` | `C:\ProgramData\BloomCE\certs\agent_server_key.pem` | Agent TLS server key |
| `VmManager:CaCertPath` | `C:\ProgramData\BloomCE\certs\ca_cert.pem` | CA root cert (trusted for client validation) |
| `VmManager:CrlPath` | `C:\ProgramData\BloomCE\certs\crl.pem` | Certificate Revocation List |

**How to configure:** Add these keys to `settings.json` (written by `deploy-agent.ps1`) or `appsettings.json`:

```json
{
  "VmManager": {
    "ServerCertPath": "/opt/vmmanager/certs/agent_server_cert.pem",
    "ServerKeyPath": "/opt/vmmanager/certs/agent_server_key.pem",
    "CaCertPath": "/opt/vmmanager/certs/ca_cert.pem",
    "CrlPath": "/opt/vmmanager/certs/crl.pem"
  }
}
```

Or via environment variables (ASP.NET Core config binding):

```
VmManager__ServerCertPath=/opt/vmmanager/certs/agent_server_cert.pem
VmManager__ServerKeyPath=/opt/vmmanager/certs/agent_server_key.pem
VmManager__CaCertPath=/opt/vmmanager/certs/ca_cert.pem
VmManager__CrlPath=/opt/vmmanager/certs/crl.pem
```

For Linux deployments, override the path keys to point to your cert directory.

## Client Certificate Issuance

The agent fetches its own server cert from an external cert server using CSR-based issuance:

1. Agent generates an RSA 2048 keypair locally
2. Agent creates a CSR with CN `bloomce-agent` and SAN entries (CN + LAN IPs)
3. Agent POSTs the CSR to `<cert_server_url>/sign-csr` with Bearer auth
4. Cert server signs and returns the cert PEM + expiry
5. Agent saves cert/key to the configured paths
6. On failure, falls back to legacy `<cert_server_url>/issue-cert` (server generates keypair)

See `ICertProvider.cs` for the provider interface and `FastApiCertProvider` / `StepCaCertProvider` implementations.

## Client Cert Validation

When `RequireClientCert` is enabled, the agent validates incoming client certificates:

- Checks cert against CA at configured `CaCertPath` (custom root trust)
- Checks CRL at configured `CrlPath` if present (offline revocation check)
- Validates client CN matches `VmManager:ExpectedClientCN` (default: `bloomce-client`)

## Configuration

The agent reads mTLS settings from **two files**:

1. **`appsettings.json`** — next to `VmManager.Agent.exe` in the install directory (default `C:\Program Files\CYZVmManager\appsettings.json`). Read by Kestrel/`AgentHost.cs` for TLS listener setup and client cert validation.

2. **`settings.json`** — in the LocalSystem AppData directory (`C:\Windows\System32\config\systemprofile\AppData\Roaming\VmManager\settings.json`). Read by `SettingsService`/`CertManagerService.cs` for cert fetching and rotation.

Both files are auto-generated by `deploy-agent.ps1` from `onprem_config.yaml`. You normally don't edit them by hand, but you can override any path.

### Example `appsettings.json`

Place at `C:\Program Files\CYZVmManager\appsettings.json`:

```json
{
  "VmManager": {
    "EnableTls": true,
    "RequireClientCert": true,
    "CertServerUrl": "https://cert-server:9090",
    "CertServerAuthToken": "your-bearer-token",
    "CertProvider": "fastapi",
    "ServerCertPath": "C:\\ProgramData\\BloomCE\\certs\\agent_server_cert.pem",
    "ServerKeyPath": "C:\\ProgramData\\BloomCE\\certs\\agent_server_key.pem",
    "CaCertPath": "C:\\ProgramData\\BloomCE\\certs\\ca_cert.pem",
    "CrlPath": "C:\\ProgramData\\BloomCE\\certs\\crl.pem",
    "CrlUrl": "",
    "ExpectedClientCN": "bloomce-client"
  }
}
```

### Example `settings.json`

Place at `C:\Windows\System32\config\systemprofile\AppData\Roaming\VmManager\settings.json`:

```json
{
  "EnableTls": true,
  "RequireClientCert": true,
  "CertServerUrl": "https://cert-server:9090",
  "CertServerAuthToken": "your-bearer-token",
  "CertProvider": "fastapi",
  "ServerCertPath": "C:\\ProgramData\\BloomCE\\certs\\agent_server_cert.pem",
  "ServerKeyPath": "C:\\ProgramData\\BloomCE\\certs\\agent_server_key.pem",
  "CaCertPath": "C:\\ProgramData\\BloomCE\\certs\\ca_cert.pem",
  "CrlPath": "C:\\ProgramData\\BloomCE\\certs\\crl.pem",
  "CrlUrl": "",
  "ExpectedClientCN": "bloomce-client"
}
```

### All mTLS settings

| Setting | Default | Description |
|---------|---------|-------------|
| `EnableTls` | `false` | Enable TLS on the API port |
| `RequireClientCert` | `false` | Require mTLS client cert validation |
| `CertServerUrl` | (empty) | Cert server base URL (e.g. `https://cert-server:9090`) |
| `CertServerAuthToken` | (empty) | Bearer token for cert server auth |
| `CertProvider` | `fastapi` | Provider: `fastapi` or `step-ca` |
| `ServerCertPath` | `C:\ProgramData\BloomCE\certs\agent_server_cert.pem` | Server cert path |
| `ServerKeyPath` | `C:\ProgramData\BloomCE\certs\agent_server_key.pem` | Server key path |
| `CaCertPath` | `C:\ProgramData\BloomCE\certs\ca_cert.pem` | CA cert path |
| `CrlPath` | `C:\ProgramData\BloomCE\certs\crl.pem` | CRL file path |
| `CrlUrl` | (empty) | CRL fetch URL (defaults to `<cert_server>/crl.pem`) |
| `ExpectedClientCN` | `bloomce-client` | Required CN on incoming client certs |

### Certs on Hyper-V VMs

VMs created by the agent run CloudEngineAutomation with the lifecycle module. The agent's cert server issues certs with CN `bloomce-agent` for the host. VMs inside Hyper-V get their own certs from the same cert server (CN `bloomce-client`) and store them in the same default location: `C:\ProgramData\BloomCE\certs\`.

## Cert Server API

The cert server (FastAPI, source at `automation_deploy/fastapi_cert_server/`) exposes these endpoints. The path is stripped from `CertServerUrl` before appending:

| Method | Path | Auth | Purpose |
|--------|------|------|---------|
| POST | `/sign-csr` | Bearer | Sign CSR, return cert PEM + expiry |
| POST | `/issue-cert` | Bearer | Legacy: server generates keypair, return cert + key |
| GET | `/ca.crt` | none | Return CA root cert PEM |
| GET | `/crl.pem` | none | Return CRL PEM |
| GET | `/health` | none | Health check |

## Key Type

RSA 2048 with SHA-256 signing. CSR includes CN as SAN DNS entry plus agent LAN IPs.

## Rotation

- Cert validity: 15 minutes
- Rotation check interval: configurable via `CertRefreshEnabled`
- CRL validity: 20 minutes
- On rotation failure, existing cert remains in use until expiry (fail-open within validity window)
